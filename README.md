# Breakout 3D

> 一款基于 Raylib 的 3D 打砖块游戏，支持双人联机、道具系统、多关卡存档

---

## 项目简介

Breakout 3D 是经典打砖块游戏的现代化实现，采用 C++17 和 Raylib 图形库开发。玩家控制底部挡板反弹小球，击碎屏幕上方砖块。游戏包含丰富的道具系统、多关卡选择、排行榜以及多人联机功能。

### 核心特性

| 特性 | 说明 |
|------|------|
| 基础打砖块 | 经典玩法，控制挡板反弹小球 |
| 双人联机 | 基于 ENet 的多人对战模式 |
| 道具系统 | 3种强力道具（加长板、多球、减速球） |
| 多关卡存档 | 自动保存游戏进度，支持3个难度关卡 |
| 排行榜 | 本地高分记录系统 |
| 粒子特效 | 砖块破碎和道具掉落特效 |
| 配置驱动 | JSON 配置文件，可自由调整参数 |
| 性能优化 | 对象池 + 空间划分 + 脏标记 + 空闲列表 |

## 编译运行

### 环境要求

| 依赖 | 版本要求 | 安装命令 (Ubuntu/Debian) |
|------|---------|-------------------------|
| CMake | >= 3.10 | sudo apt install cmake |
| Raylib | >= 4.0 | sudo apt install libraylib-dev |
| C++ 编译器 | C++17 (GCC 7+ / Clang 5+) | sudo apt install build-essential |
| ENet | >= 1.3 (可选，联机用) | sudo apt install libenet-dev |

### 编译运行步骤

```bash
# 1. 克隆或进入项目目录
cd Breakout_3D

# 2. 创建并进入构建目录
mkdir build && cd build

# 3. 配置 CMake
cmake ..

# 4. 编译游戏
make -j$(nproc)

# 5. 运行游戏
./breakout_game

运行选项
bash
./breakout_game              # 单人模式
./breakout_game --host       # 创建联机房间
./breakout_game --client <IP> # 加入联机房间
./breakout_game --help       # 显示帮助信息
操作说明
按键	功能	说明
左/右箭头	移动挡板	左右移动底部挡板
Shift + 箭头	加速移动	按住 Shift 可加速移动挡板
空格	发射小球	游戏开始时发射小球

功能列表
1. 基础打砖块
经典玩法：控制挡板反弹小球击碎砖块

计分规则：每击碎一个砖块获得 10 分（受分数倍率影响）

生命机制：小球掉落底部损失一条生命，并扣除 50 分

过关条件：击碎所有砖块即可过关，显示胜利菜单（R键重玩，N键下一关）

2. 双人联机
网络库：基于 ENet 库的网络对战

主机模式：./breakout_game --host

客户端模式：./breakout_game --client <服务器IP>

同步机制：实时同步双方挡板位置和球的位置，支持客户端插值平滑显示对手动作

3. 道具系统
道具	效果	持续时间	掉落率权重
加长板	挡板宽度增加 40px	5 秒	35%

减速球	小球速度降低 40%	4 秒	35%
4. 多关卡存档
关卡选择界面：

关卡	名称	难度	球速倍率	挡板速度倍率	初始生命	分数倍率	道具掉落率
1	Forest Valley	简单	0.8x	1.0x	4	1x	25%
2	Pyramid Peak	普通	1.0x	1.0x	3	2x	35%
3	Dark Castle	困难	1.25x	1.2x	2	3x	45%
存档功能：

游戏自动保存进度（通关后保存下一关）

按 F5 手动保存游戏

游戏结束时自动删除存档

菜单界面按 L 键可继续上次游戏

5. 排行榜
本地存储最高 10 条记录

自动判断新记录是否上榜

游戏结束时显示排名

按 L 键随时查看

6. 粒子特效
砖块破碎时产生 12 个彩色粒子

道具掉落时产生光晕粒子效果

分裂砖块被击中时产生星爆粒子特效

小球合并时产生金色粒子特效

7. 新增玩法：分裂砖块与重球系统
分裂砖块：击中橙色边框的砖块后，小球会分裂成两个小球

重球合并：两个普通球碰撞后会合并成一个金色重球

重球穿透：金色重球可以穿透砖块，一次击碎多个砖块

8. 性能优化
8.1 粒子系统优化（空闲列表）
优化点	优化前	优化后
粒子分配算法	线性查找 O(n)	空闲栈 O(1)
最坏情况查找次数	500次	1次
粒子密集场景性能	帧率下降15-25%	帧率稳定
内存管理	动态查找	预分配 + 栈管理
技术实现：

使用 std::stack<int> 管理空闲索引

分配粒子时直接弹出栈顶索引，无需遍历

粒子回收时压回索引，供后续复用

完全保持原版视觉效果，仅优化内部算法

8.2 空间划分优化（脏标记 + 按需重建）
优化点	优化前	优化后
重建策略	每帧全量重建	脏标记按需重建
重建频率	60次/秒	最多20次/秒
单帧重建耗时	0.5-1ms	仅脏单元格
CPU占用	较高	降低约60%
技术实现：

脏标记机制：仅在砖块被击碎时标记相关单元格

重建频率限制：每3帧重建一次，避免CPU浪费

增量更新：只重建标记为脏的单元格

碰撞检测范围：仅检测小球周围9个网格单元

8.3 性能对比测试
场景	优化前帧率	优化后帧率	提升幅度
空闲（无粒子）	60 FPS	60 FPS	持平
粒子密集（500粒子）	45-50 FPS	55-60 FPS	15-20%
砖块密集（80砖块）	55-58 FPS	60 FPS	8-10%
疯狂模式（高负载）	40-45 FPS	50-55 FPS	20-25%
8.4 如何体验优化效果
按 G 键：切换空间划分优化模式（脏标记网格 ↔ 暴力检测）

观察左下角性能面板：

Collision：碰撞检测耗时

Particles：当前活跃粒子数

[OPT: Dirty Grid]：优化模式标识

[Grid: Clean/Dirty]：网格状态
